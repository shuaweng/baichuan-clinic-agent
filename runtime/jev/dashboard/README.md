# Jev 动态评估看板

在项目根目录启动：

```sh
python3 scripts/jev-dashboard.py start
```

访问 http://127.0.0.1:3081 。DSH 仍在 3080，两者独立运行。停止和查看服务状态分别用 `stop`、`status`。

## 操作

- **结果回放**：默认显示100轮完整结果；可按1/4/10条每秒逐条回放、暂停和恢复。不调用模型。
- **QA 明细**：搜索或按人群、产品信号筛选，点选查看完整问题、真实回答及前文。手动选择会固定样本，点“恢复跟随”回到最新一条。
- **Jev 判断**：六个独立维度，点击每行展开全部候选概率。未返回的维度显示等待/失败状态，不填零分或沿用历史标签。
- **实时评估**：选择当前QA、前10条、筛选结果或全100条，创建独立批次。通过原有 AI SDK / Vercel Gateway 调用 `typesafe-ai/jev`。
- **暂停**：当前请求返回后停止后续调度；继续会跳过成功请求。重试失败项不会覆盖成功结果。服务重启后未完成批次标记为中断，结果未知的请求需要显式重试。
- **导出**：下载当前显示范围的QA、原始概率、请求记录与派生信号。

## 数据和指标

样本只使用 `data/session-batch-50/` 这一批新编问题及真实DSH回答。`jev-timeline.json` 从原来的200份成功记录导出并验证输入指纹，保留原始耗时、时间、用量和费用。历史抽查笔记不是Jev输出，仅在历史模式显示。

历史回放顶部“总耗时”呈现已显示样本对应的原始批次时间，不是播放动画耗时。“Jev 上游耗时”单独汇总网关记录的两次成功上游调用时间，不代表纯模型推理或本地端到端耗时；缺失显示“—”。其下另列整轮记录：历史记录包含旧脚本的调度等待，实时请求合计不包含排队。实时总耗时包含排队、暂停与重试。失败尝试未返回的费用无法统计。历史回放不会将已经评估完的数据重新计为待评估。

累计成本汇总网关 `cost`，`marketCost` 单独保留。费用未知显示“未返回”，网关返回0才显示0；不将参考费用冒充实际账单。

能力缺口、badcase、不满和判断摇摆均为待复核信号，不能直接称为已验证的新需求或医学错误。阈值延续首批规则，尚未校准。没有把分类概率合成为医学质量总分。

## 运行与恢复

环境变量 `AI_GATEWAY_API_KEY` 从项目 `.env.local` 加载，仅存在于服务端。页面无法读取密钥。服务只绑定127.0.0.1，写操作检查本地主机、来源与每次启动生成的请求令牌；静态文件使用固定白名单。

实时输入使用 `.local/maternal-fresh-50-20260922/jev-state/` 中裁剪后的100份state。缺少本地输入或网关key时仍可回放，实时按钮禁用。运行记录保存在 `.local/jev-dashboard/runs/`，不覆盖基线结果，也不进入Git。

调度最多每2.5秒启动一个请求。429与临时5xx按Retry-After及退避规则重试，401/403暂停批次，不自动循环。每份结果核对输入指纹。多页打开同一看板，通过SSE同步批次状态，后端只允许一个批次执行。

```sh
npm --prefix runtime/jev test
npm --prefix runtime/jev run dashboard:history
```

测试使用临时目录和注入的本地评估函数，不调用付费模型。历史导出也不调用模型；已有 `jev-timeline.json` 时无需重复导出。
