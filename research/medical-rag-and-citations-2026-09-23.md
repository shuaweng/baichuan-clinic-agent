# 百川妇幼专科 Agent：回答时的 RAG 与引证

本轮目标：让医生的提问经过资料检索，再形成能够追溯依据的回答。知识库服务于 Agent 回答，JEV 可在事后检查回答与证据的关系。Query 集用于覆盖任务，不必逐条来自指南或真实咨询库。

## 1. 可用的医疗素材

资料的“开放可复用”与软件的“开源”不同，不能由 GitHub 仓库的代码许可证推断其中所有医学文本可商用。

| 来源 | 合适的医生任务 | 获取和使用边界 | 本项目状态 |
| --- | --- | --- | --- |
| [WHO SMART Guidelines / DAK](https://smart.who.int/) | 孕产保健、产后随访、计划生育等的指南推荐与结构化规则查证 | 各发布包分别核对许可、版本、适用人群；本次 PNC 和 CCC 包为 CC BY-NC-SA 3.0 IGO，非商业范围，不等于获得商业产品授权 | 下载 PNC、CCC 决策表，保留表名、行号、表头及合并单元格定位；不是完整底层指南全文 |
| [LactMed](https://www.ncbi.nlm.nih.gov/sites/books/NBK547439/) | 哺乳期用药、乳汁暴露、婴儿影响与备选药物的证据查找 | 官方明确可免费批量下载，推荐 LitArch OA；遵循 NLM 署名、更新、翻译等条款 | 后续最值得扩充的专题库，尚未导入 |
| [CDC 临床资料](https://www.cdc.gov/other/agencymaterials.html) | 儿童生长发育、避孕咨询、特定疾病与预防主题 | 多数机构材料可复用，第三方内容例外；保留出处，不暗示机构背书；美国适用背景需明确 | 已导入四段英文原文摘录：生长、发育监测、避孕共同决策、儿童轻型颅脑损伤；并非四本完整指南 |
| [PMC Open Access Subset](https://pmc.ncbi.nlm.nih.gov/tools/openftlist/) | 妇科、儿科的系统综述、开放指南和专题研究 | 用官方允许的下载渠道，逐篇查看许可；PMC 全站不等于 OA 子集；论文也不自动等于推荐指南 | 可扩展全文来源，尚未导入 |

中文资料可补充国家卫健委等公开规范，以及获得授权的学会指南、医院制度和药品说明书。公开可读不自动等于可打包再分发，导入时逐项记录授权与来源。现有咨询 QA 更适合问题发现、术语和任务覆盖，不作为临床知识库的主要权威依据。

妇幼范围必须覆盖女性全生命周期和 0–18 岁儿童。首批资料只是小范围起点：不能把产后资料当作全部妇科，不能把新生儿和五岁以下资料当作全部儿科。

## 2. 开源 RAG 方案及选型

| 方案 | 可利用的能力 | 对当前项目的判断 |
| --- | --- | --- |
| [Haystack](https://github.com/deepset-ai/haystack)（Apache-2.0） | 文档存储、关键词/向量检索、过滤、重排、可组合管线；可用 Hayhooks 暴露 HTTP/MCP | 当前采用。保留 DSH 作为 Agent，只挂接检索和原文读取工具，便于控制证据元数据 |
| [LlamaIndex](https://developers.llamaindex.ai/python/examples/query_engine/citation_query_engine/)（core 为 MIT） | 文档索引、检索器和 CitationQueryEngine；引用可对应更细的来源片段 | 同样可行，尤其适合直接构建文档问答；托管解析服务与开源 core 应分开评估。当前不叠加第二套框架 |
| [RAGFlow](https://github.com/infiniflow/ragflow)（Apache-2.0） | 文档解析、知识库管理、切片干预、带引用的问答界面 | 如果下一阶段重点是医生上传文件及管理知识库，可选独立后端。官方 quickstart 要求至少 16 GB RAM、50 GB 磁盘，ARM 没有官方维护的预构建镜像；当前 Mac 本地接入成本更高 |

数据流：医生问题 → DSH 提炼检索词 → Haystack 检索及人群过滤 → 读取候选原文 → DeepSeek 基于证据形成回答 → 句旁引用 → 医生查看原文。

当前检索是 Haystack 2.22.0 的 BM25，加有限中英主题词映射，无向量模型、无 reranker。它已经属于 RAG 检索链路，但不应称为成熟的跨语言语义检索。后续可在同一框架内增加多语种 embedding、BM25 + 向量混合召回、重排；新增模型前评估资源和召回收益。

医学切片应按推荐/小节保留上下文：适用对象、前提、例外、禁忌和表头不可被独立截断。文档入库同时保存机构、标题、日期、版本、地区、人群、许可、原始 URL、页码/表格行号、原文及校验值。不要只保存一段丢失出处的文本。

## 3. 面向医生的引证交互

推荐设计为“句旁编号 + 证据侧栏”，不是只在文末罗列参考链接。

1. **回答正文**：重要临床结论后出现 [1] [2]。一个编号对应具体被引用的原文片段；没有来源的推断明确说明依据不足，不给它套引用。
2. **悬停预览**：展示资料短标题、机构、年份及一句原文摘要，让医生不离开当前阅读位置。
3. **点击侧栏**：上方显示“正在支撑的回答句子”，下方显示高亮原文及相邻上下文，再列适用人群/地区、版本、章节或表格行号。“查看原文”跳转官方页面或 PDF 指定页。
4. **来源有冲突时**：并列展示两份资料的适用条件和年份，不静默混成一个结论。若只是引用到相关资料，不能显示“已证实”。
5. **证据不足时**：在对应结论旁明确“未找到适用依据”，说明缺的是年龄、药物剂量、当地规范等哪一项，提供继续检索或补充资料入口。

来源类型（指南/系统综述/原始研究/本院制度）和支持关系（支持/部分支持/不支持）是两个维度，不能混用。只有原文带有 GRADE 等分级时才原样展示分级，不根据机构名自动赋予最高等级。检索相关性分和 JEV 的标签概率也不是医学可信度。

产品参考：

- [UpToDate Expert AI 官方说明](https://www.wolterskluwer.com/en-gb/news/uptodate-expert-ai-genai-clinical-decision-support)：借鉴从生成回答返回专业内容、展示依据与假设的交互；其商业内容授权不随功能模仿获得。
- [LlamaIndex CitationQueryEngine](https://developers.llamaindex.ai/python/examples/query_engine/citation_query_engine/)：编号到 source node 的技术实现参考。
- [TypeSafe citation_check](https://docs.typesafe.ai/cookbooks/citation_check)：先核对引用原文是否存在，再判断原文与结论是否支持/矛盾/无关。适合事后质检，不代替医学审核。

建议引证数据结构：claim_id、answer_span、source_id、chunk_id、exact_quote、quote_offsets、locator、source_version、content_hash、support_status。服务端验证 ID 和原文，前端只渲染已经解析成功的引用。外部文档作为数据处理，不能作为对 Agent 的指令。

## 4. 本轮实际接入边界

- `data/medical-kb/`：6 个来源、937 个片段，其中 703 个来自特定人道主义紧急情境儿童资料。普通诊室检索默认排除它，只有问题明确涉及该情境时启用；因此普通模式可检索 234 个片段。
- `runtime/medical-kb/`：Haystack Python 工作进程 + DSH 工具适配；查询在本地检索，不调用额外模型或远程检索服务。被选作回答依据的片段仍会进入现有 DeepSeek 模型上下文。
- 三个 AgentPreset 新增 `medical_kb_search`、`medical_kb_read`、`medical_kb_sources`；prompt 要求临床证据问题先查再答、核对适用性、只引实际读取来源。
- 当前界面复用 DSH 的来源卡和 Markdown 链接；本报告中的悬停卡、逐句证据侧栏、原文高亮及 JEV 引证审查属于后续设计，尚未完成 UI 开发。
- 测试覆盖主题检索、空结果、伪造引文、特定情境过滤和 DSH 工具定义。技术连接通过不等于临床内容已审核或召回率达标。

验证下一阶段应抽查“是否找到了应该找到的来源、引用是否真的支撑那句话、适用人群是否正确、依据不足时是否表达了缺口”，而不是强求 Query 集本身来源严格。

实际验证：4 项 RAG 测试和 13 项现有诊室界面/数据测试通过。真实 DSH 验证会话 `session-f81b2917-9d6e-56e7-bed4-5dfe4aafb7fd` 完成，读取 CDC 发育原文后生成了同一官方页面的引用。该轮最初两次调用超出检索条数上限，模型调整后成功；已在工具参数描述中补充 1–6 的范围。此单次验证仅证明检索、原文读取和回答链接链路有效，不代表全面医学质量评测。
