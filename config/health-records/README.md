# 健康档案

已选入口：浅橙色胶囊。点击后以原生模态右侧抽屉打开，保留当前 DSH 对话。

## 数据与交互

- `core.js`：IndexedDB 成员与文件存储、输入校验、版本冲突检测、按会话隔离的一次性授权快照。
- `panel.js`：React 入口、档案编辑、成员管理、报告上传/预览/移除、报告要点与选用控制。
- `panel.css`：桌面及移动端布局、原生 dialog 焦点管理、减少动态效果支持。
- `scripts/apply-dsh-branding.py`：对固定的 DSH `0.1.5-rc.2` 做有数量校验的可重复覆盖。源代码与样式在仓库内维护，安装包可由 npm ci 重建。

档案和原始资料保存在当前浏览器、当前站点的 IndexedDB 中，无后台同步。清除网站数据会删除档案。成员与报告没有真实默认医学值；空白是未知，不代表“无病史”。文件格式为 PDF/JPEG/PNG/WebP，核对 MIME 和文件签名；单份上限 10 MiB，每个成员 30 份，总计 100 MiB。

## 提供给 Agent 的内容

只有用户勾选“本次咨询使用此档案”并保存后，所选健康字段和所选报告的手动要点才冻结为快照。原文件不会自动识别或发给模型。入口下方显示对象与“下次提问使用”，可以撤销。

在 DSH 的 `InputHub.sink` 正常发送路径拼入文本：保留原提问、附件顺序、发送模式和取消信号。成功后消费授权；失败保留用于重试；不同 Session 不共享选择，刷新页面会清除尚未发送的授权。已发送快照属于该会话历史；删除本地档案不能撤回已发送内容。命令通道不自动注入档案。

档案中的文件、病史、报告要点是待分析资料，不应作为指令执行。临床预设同步说明这一资料边界。

## 验证和启动

```sh
npm ci --prefix runtime/health-records
python3 scripts/apply-dsh-branding.py
npm --prefix runtime/health-records test
python3 scripts/dsh-local.py stop
python3 scripts/dsh-local.py start
```

测试使用独立的内存 IndexedDB、测试专用 DOM 与伪造的发送端，不读取真实浏览器健康数据，也不向模型发送测试内容。覆盖持久化、成员隔离、文件校验、删除、并发修改、授权撤销/单次消费/失败重试、原 DSH 发送接线和抽屉交互。原生浏览器 PDF 显示取决于浏览器支持，可从预览面板下载原文件查看。
