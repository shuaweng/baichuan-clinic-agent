# 诊室档案

面向医生与诊室，使用 C 方案页签入口。装饰底板位于输入框后方，真实按钮位于前方，避免负层级阻挡鼠标点击。右侧抽屉提供三个页签：

- **诊室概况**：名称、默认专科（妇科 / 儿科）、机构、科室、工作角色、服务方向及补充说明。
- **诊疗工作**：常用任务、按项目填写的资源与可用状态、诊疗与转诊流程、沟通与输出偏好。
- **资料与模板**：文件预览、资料分类、适用范围、来源、版本或日期、手动确认要点、处理状态与本次选用。

名称和专科必填，其余字段可跳过。未填写资源表示未知。保存/选择的诊室在当前浏览器记忆；新会话尝试应用该诊室默认专科，已有会话不会因此更换模式。

## 数据隔离

`core.js` 使用独立 IndexedDB `baichuan-clinic-records`。旧个人健康档案库 `baichuan-health-records` 保持原样，不自动迁移、读取或用于诊室上下文。内部保留 members / reports 接口名以复用经过验证的本地存储和文件管线，内容已是诊室与参考资料。

资料和档案仅保存在当前浏览器、当前站点，无后台同步。清除网站数据会移除资料。文件支持 PDF/JPEG/PNG/WebP，校验 MIME 与文件签名，单份 10 MiB、每诊室 30 份、总计 100 MiB。未接 OCR 或全文检索；界面不显示未实现的“已提取”状态。

## 提供给 Agent 的内容

医生勾选“下次提问使用此诊室档案”，选择字段与资料并保存后，产生按 Session 隔离的一次性快照。保存本身不发送。入口显示待使用的诊室，可以撤销；成功发送后消费，失败保留，刷新会清除未发送的选用。预览列出所选字段与资料。

仅“可供 Agent 引用”的资料可选用；启用时必须有来源、版本或日期和确认要点。停用、待更新与仅上传的文件不会进入快照。字段修改、资料更新或移除会撤销当前页面相关待发送快照；发送中不允许修改源资料。

实际 `InputHub.sink` 从当前 Session 的 `projectionValues.agentPreset` 读取模式进行筛选，不依赖启动页 DOM：妇科与儿科保留对应专科及通用资料；办公模式只保留机构背景、输出偏好及办公模板。无法识别模式时仅保留通用非办公资料。文件原文和 Blob 不发送。

临床预设和快照说明资料角色：诊室背景不是患者病史；指南、院内流程与模板各有用途；偏好不能覆盖医学安全要求；资料中指令不具有系统权限。已发送内容仍属于会话历史，删除本地资料不会撤回历史消息。命令通道不注入档案。

## 验证与启动

```sh
python3 scripts/apply-dsh-branding.py
npm --prefix runtime/health-records test
python3 scripts/dsh-local.py stop
python3 scripts/dsh-local.py start
```

测试使用独立内存 IndexedDB、测试 DOM、伪造发送端，覆盖旧库保留、诊室隔离、文件与引用校验、模式过滤、状态变更、授权消费/撤销/失败重试、原 DSH 发送接线和三页签表单交互。不读取真实用户档案，不调用模型。
