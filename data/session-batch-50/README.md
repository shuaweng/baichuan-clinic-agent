# 新编50组妇幼 Session

本批根据2026-09-22用户要求全新编写，没有读取或复用项目已有 docs、旧 query 数据或 mock Answer。只读取当前运行配置及 DSH 程序接口定义，用于保证调用的是现有妇幼专科模式。

## 样本构成

每组2轮连续对话，50个独立 DSH Session，共100轮。10个采样组各5个：青春期女性、成年女性妇科、生殖健康与筛查、孕期与分娩准备、产后与哺乳、新生儿与婴儿、幼儿与学龄前、学龄儿童与青少年、围绝经与老年女性、产品能力与流程需求。

用户问题是新编的合成情境；第二轮为预先设计的信息补充、纠正或后续任务，不是根据第一轮答案动态模拟的真实患者。助手回答由运行中的 DSH 经其认证会话接口实际生成，使用妇幼专科模式及 deepseek-flash / high。没有直接绕过 DSH 调模型，也没有手写、补齐或润色助手回答。

所有会话使用独立工作区 `.local/dsh-batch-workspace`，标题为 `[50组] Sxxx 主题`。用户原来的会话保持不变。原始压缩事件仍由 DSH 保存。

## 文件

- `scenarios.jsonl`：50组新编输入，采样组只是作者元数据，不是评估金标准。
- `sessions.jsonl`：完整生成后导出的50个会话，含真实回答、模型、提示词指纹、事件来源和完成状态。
- `sessions.md`：供逐轮阅读的完整问答。
- `index.csv`：100轮索引，可按主题、采样组、长度和耗时筛选。
- `summary.json`：数量、完整性、提示词一致性和 DSH 报告的 token 用量。
- `.local/maternal-fresh-50-20260922/jev-state/`：100份逐轮裁剪输入，包含当前 QA 和必要历史，不包含采样组、作者预期、内部推理、token流、系统提示词全文或认证信息。

每轮输入都能通过 session id 和事件编号追溯。只有完成的轮次才进入交付；空回答、失败轮次和历史截断会阻断完整导出，不会被替换成伪造回答。用量原样汇总 DSH 字段，不将 cache/token 的不同供应商含义混算为费用；标题生成等内部调用不一定包含在对话用量内。

## 复现

在项目根目录运行。批次标识固定，重跑会跳过已完成样本，不重新收费生成完成的回答：

```sh
python3 scripts/run-dsh-session-batch.py --limit 50 --workers 3
python3 scripts/export-dsh-session-batch.py
```

脚本遇到未确定是否入队的请求不会自动重复发送，避免一条问题提交两次；遇到失败会保存状态以便排查。命令会使用当前 DSH 中配置的模型账户额度。

本批未做医学正确性审核。2026-09-22 已完成 Jev 首轮打标：100轮分别做 query / qa 评估，200次成功请求、600个判断，规则版本 `maternal-gateway-0.1`。题材刻意覆盖多种情况，不能用各组数量代表真实用户需求占比。若用于评估开发和测试，须按 Session 划分，不能将同一 Session 的两轮拆进不同集合。

## Jev 结果

- `jev-report.html`：可本地打开的交互报告，筛选候选、查看完整问答、历史与概率，无外部网络请求。
- `jev-report.md`：结果分布、定向抽查发现与下一版评估建议。
- `jev-labels.jsonl` / `jev-labels.csv`：100轮结构化标签；JSONL保留完整概率、问答、指纹和独立的 Codex 抽查笔记。
- `jev-summary.json`：队列统计、用量及网关原始费用字段。
- `jev-evaluation-contract.json`：本次产品能力快照、题目和复核阈值。

自动标签与 Codex 产品行为抽查分开保存；抽查不是医学审核或人工金标准。自动 badcase 为0不意味着所有回答合格，报告内记录了漏判与误报线索。

```sh
npm --prefix runtime/jev run batch -- --retry-failed
npm --prefix runtime/jev run report
```

批次脚本全局限速到最多每2.5秒启动一次请求，遇429与临时5xx退避重试，跳过已经成功且输入指纹一致的结果。输入或题目变更会阻止覆盖冻结批次。报表导出本身不调用模型，并验证200份请求指纹及结果完整性。
