# 妇幼 Agent 资源与工具选型

核查日期：2026-09-22。依据原作者仓库、官方文档和发布机构资料。下面是选型研究，不是安装清单或医学审核结论；本次尚未连接任何第三方医疗 MCP、下载全量医学语料或上传患者数据。代码开放、内容开放获取、内容可再分发，是三个不同问题。

## 建议首版组合

用 DSH 管理对话、工具调用与会话事件；建立小型、经审核的妇幼知识库；先做就诊准备单保存和读取。文献检索在 PubMed MCP 与 BioMCP 中二选一，按需接入。Jev 作为异步质量与需求评估层。暂不引入完整医院信息系统、诊断多 Agent 框架或大规模医学语料。

## 优先资源

### 1. WHO SMART：产前、产后照护的产品与知识结构

- [产前照护 DAK 官方出版页](https://www.who.int/publications/i/item/9789240020306)
- [smart-anc 开源实现资料](https://github.com/WorldHealthOrganization/smart-anc)
- [产后照护 DAK 当前发布页](https://smart.who.int/dak-pnc/)
- [WHO SMART 总览](https://www.who.int/teams/digital-health-and-innovation/smart-guidelines)

DAK 包含用户角色、使用场景、业务流程、数据字典、决策支持和指标，适合定义应该追问什么、哪些信息需要保留以及如何验收。smart-anc 提供可计算知识实现资料。优先借鉴这些结构，再做中国服务环境下的适配，不能直接把国际推荐频次当成当地医院安排。

许可要按具体材料区分：[smart-anc 仓库 LICENSE](https://github.com/WorldHealthOrganization/smart-anc/blob/master/LICENSE.md) 为 CC0 声明；产前 DAK 出版物及[产后 DAK](https://smart.who.int/dak-pnc/license.html) 标注 CC BY-NC-SA 3.0 IGO。仓库许可证不能自动替代出版物或第三方材料条款。首版保存来源和版本，不做未经审核的临床规则自动执行。

### 2. PubMed MCP：首选的窄范围文献检索候选

- [cyanheads/pubmed-mcp-server](https://github.com/cyanheads/pubmed-mcp-server)
- Apache-2.0；支持 stdio 与 Streamable HTTP。
- 文档列出 PubMed 搜索、文章信息、可用全文、MeSH 查询和引文格式化等工具。

适合为问题找到可追溯的文献与 PMID。建议在业务层只开放“搜索证据”和“读取来源”两个窄入口；保留发布日期、研究人群、文献类型和取回状态。其 MCP prompt/resource 能力不要假设在 DSH 内可用：当前安装的 DSH MCP 客户端仅桥接 tools。

本次只核查文档，未测试延迟、召回或中文查询效果。后续验收需要测试英文检索词转换、孕期与哺乳期的区分、无结果、限流及全文不可用。代码许可证不覆盖检索回来的所有论文版权。不应向公开托管 MCP 发送完整个人病历；可以部署本地连接器，仅发送必要的去标识检索词。

### 3. BioMCP：更广的医学研究工具备选

- [genomoncology/biomcp](https://github.com/genomoncology/biomcp)
- [上游数据源与许可](https://github.com/genomoncology/biomcp/blob/main/docs/reference/source-licensing.md)
- MIT；既有 CLI，也有 MCP。

整合 PubMed、Europe PMC、ClinicalTrials.gov 等来源，也包含较多基因、变异和肿瘤研究能力。对我们最有用的是文章搜索与资料获取；其他能力暂不加入患者端。官方提醒 Python 发行包为 `biomcp-cli`，不是同名 `biomcp` 包。

与 PubMed MCP 有明显重叠，首版二选一。推荐先试较窄的 PubMed MCP；若后续需要多个生物医学数据源，再评估 BioMCP。README 的“可信来源”不构成对每条结果的医学审核。不同上游的 API key 和再利用条款分别适用。

### 4. Docling / Docling MCP：知识入库和报告文字提取

- [Docling](https://github.com/docling-project/docling)
- [Docling MCP](https://github.com/docling-project/docling-mcp)
- MCP 代码为 MIT，所用模型需按各自许可核查。

将 PDF 转成结构化内容，可用于指南入库、保留表格与来源定位。MCP 支持本地或远程转换；首版建议作为后台入库步骤，用户上传报告功能后置。实际接入前用中文扫描件验证页码、数值、单位和表格行列关系。文档识别工具不负责医学解读，也不能把未识别区域当作正常。

## 妇幼相关的公开知识来源：不一概称为开源软件

### 5. LactMed：哺乳期药物资料

- [NLM 官方访问说明](https://www.nlm.nih.gov/toxnet/Accessing_LactMed_Content_from_NCBI_Bookshelf.html)
- [LactMed Bookshelf](https://www.ncbi.nlm.nih.gov/books/NBK501922/)

适合为哺乳期用药信息查询补充来源。NLM 说明可通过 Bookshelf、PubMed 和 PubChem 查找；例如 PubMed 的 `pmcbook LactMed` 可定位相关记录。本次 Bookshelf 正文受到浏览器验证限制，已读到 NLM 官方访问说明，未验证批量下载或专用 MCP。

建议以后做只读适配器，返回成分名称、原始记录、更新日期和来源。先澄清具体药物与适用人群；不要把哺乳期结论用于孕期，也不由检索结果直接决定个体停药换药。再发布全文前核对记录条款。

### 6. 国家卫生健康委公开规范及医院就诊说明

- [国家基本公共卫生服务规范第三版修订说明](https://www.nhc.gov.cn/jws/s3578/201703/aefef3d0b2a14279b76ad57d7e7a2c4e.shtml)
- [0～6 岁儿童健康管理服务规范 PDF](https://www.nhc.gov.cn/ewebeditor/uploadfile/2017/03/20170329103413888.pdf)

对中文用户的就诊流程与公共卫生服务语境更相关。上述是较早发布的材料线索，不应宣称已核实为截至 2026 年的全部现行要求。修订说明正文抓取返回 412，搜索可定位；入库前应取得正文、检查后续修订和地区适用性。医院建档、检查准备及预约规则要单独记录机构和生效时间。

这类官方公开资料不等于整个网站内容具有统一开源许可。首版可建立来源索引，再逐条加入允许使用且完成审核的内容。

## 有价值但后置的开源项目

### 7. Synthea：合成健康记录

[synthetichealth/synthea](https://github.com/synthetichealth/synthea)，Apache-2.0。支持生成合成健康记录，导出 FHIR、CSV 等格式。可用于未来验证档案读取、不同患者信息隔离和数据缺失。默认人口和服务语境偏美国，不代表中国妇幼用户分布，也不是对话数据或医学金标准。暂不为首版部署 FHIR 服务器。

### 8. MedRAG：医学 RAG 对照实验参考

[gzxiong/MedRAG](https://github.com/gzxiong/MedRAG)，原仓库地址已重定向。它适合作为医学检索增强生成的实验参考，而非可直接上线的中文妇幼知识库。[当前 LICENSE](https://github.com/gzxiong/MedRAG/blob/main/LICENSE) 是美国政府工作 Public Domain Notice；外部语料仍需分别核查。优先借鉴检索与评估设计，不先拉取大语料或再引入一套完整 Agent 运行时。

## 我们的 Agent 应如何体现专科性

专科性由五部分共同定义：服务对象与目标、提示词、经审核且有版本的知识、最小业务工具集、可复核的评估标准。

已写入 [提示词 v0.1](../config/maternal-agent/system-prompt.v0.1.md) 和 [工具计划 v0.1](../config/maternal-agent/tool-plan.v0.1.json)。提示词当前明确只有文本能力；计划文件所有工具均未连接。原有 `product-profile.demo.v0.2.json` 是此前模拟能力设定，不能当作已部署 Agent 的能力说明。

建议 P0 工具是 `search_guideline`、`calculate_care_timeline`、`save_visit_brief`、`get_visit_brief`。日期计算交给确定性代码，只处理已有基准，不自行决定诊疗日期。P1 再接文献与哺乳期参考查询，P2 加报告读取。通用 shell、任意文件访问和医院交易工具不进入患者侧预设。

知识条目建议统一字段：`source_id`、标题、发布机构、版本/日期、人群、阶段、地区、原始 URL、章节/页码、内容、许可、审核状态。原文证据与本地解释分开存储；未审核材料不能悄悄升级为已审核知识。

Jev 使用会话消息、工具结果及版本快照进行异步评估：多余追问、阶段混淆、证据不支持、工具失败后虚报成功、诉求未完成、能力扩展候选。保留医生复核入口；不能由 Jev 分数直接批准医疗建议。

## 接入验收

每个候选组件先做固定小样本验收：正常返回、无结果、超时、来源不可用、对象/阶段不匹配、检索内容夹带指令。记录实际耗时与结果，不用 star 数或 README 宣传代替质量结论。先完成一个完整工具任务的可验证成功/失败，再批量生成会话。
